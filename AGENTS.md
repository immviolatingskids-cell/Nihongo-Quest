# Repository Guidelines

## Project Structure & Module Organization

Nihongo Quest is a browser-based Japanese learning game using native ES modules.

- `src/` contains application screens (`app.js`), learning/state engines (`engine.js`, `state.js`), content registries, audio, companion behavior, scene presentation, and `styles.css`.
- `tests/` contains Node’s built-in test suites for engine, audio, culture, and scene contracts.
- `assets/` contains approved runtime artwork and derivatives, organized into `culture/`, `shop/`, and `garden/`.
- `docs/` contains milestone records and art handoffs; `scripts/` contains validation/report utilities.
- `index.html` is the browser entry point. `dist/` is generated by the build and should not be edited manually.

## Audit & Verification Guidelines

- **Browser-Only Inspections:** Always use the internal browser skill or local headless Chrome for visual/layout audits. **Never attempt native OS desktop screen capture (`@oai/sky`).**
- **Fast-Path Audits:** Restrict visual and logic checks to local unit tests (`npm test`) and local browser DOM rendering. 
- **Build Scope:** Skip full production builds (`npm run build`), culture/audio reports, and remote git/commit verifications during routine visual or component audits unless explicitly requested in the goal prompt.
- **Completion Rule:** Stamp goals complete immediately as soon as local tests pass and the target DOM elements, layers, or assets are verified in the local browser render.

## Build, Test, and Development Commands

```bash
npm test                    # Run all regression tests
npm run build               # Copy source and assets into dist/
npm run culture:report      # Validate cultural catalogue coverage
npm run audio:report        # Report audio asset/provider coverage
