# Nihongo Quest v0.6 — Quest Journey

## Architecture

Quest Journey is a presentation and orchestration layer over the existing `curriculum` array and v0.3 learning engine. `JOURNEY_CHAPTERS` groups the existing curriculum node IDs into five readable regions; it does not add a second curriculum database or duplicate completion truth. The Journey map derives node status, progress, prerequisites, and future metadata from the current save.

Every available Journey node starts through the same session/question/answer path used elsewhere. Vocabulary and kana nodes use `curriculumItems()` and `startSession()`, grammar nodes call the existing idempotent grammar completion, and story nodes use the existing conversation session. The canonical recorder remains responsible for mastery, XP, Garden effects, Sakura events, and duplicate-attempt protection.

## Recommendations

`recommendNext()` returns structured deterministic data: action, title, reason, commitment, and destination/session information. An unfinished active session wins first. For a learner returning after three or more days, familiar due material or a 2-minute Focus Quest is preferred. Otherwise the first unlocked incomplete curriculum node is recommended, followed by known due reviews, mistakes, or Focus Quest fallback. New/unseen words are not treated as due recommendations merely because they have never been attempted.

Home now leads with Continue or Recommended next, keeps the existing Focus Quest as an explicit low-friction alternative, and links to the dedicated Journey map. Reasons use learner-facing language such as “This lesson moves your current chapter forward,” “These words are ready for a gentle return review,” and “You stopped here last time.”

## Map, chapters, prerequisites, and detail

The map presents five bounded chapters and the learner’s surrounding curriculum area. Nodes are visibly distinguished as completed, recommended, available, locked, or future. Locked nodes name the prerequisite title instead of showing a generic lock. Selecting a node opens a compact detail panel with objective, content type, estimated time, completion percentage, and what must be completed before it can begin.

Chapter progress is the average of meaningful node completion: mastered vocabulary in a vocabulary node, strengthened kana in a kana node, learned structures in a grammar node, and completed conversation for a story node. Overall curriculum progress continues to come from completed curriculum nodes, not XP or implied fluency.

Node metadata includes reserved `audioAvailable`, `discoveryId`, and `artwork` fields in the derived representation. They are currently false/null and do not expose unavailable audio or cultural collection systems. These hooks allow future Voices of Japan, Cultural Discovery, and bespoke artwork work without coupling Journey logic to asset files.

## Milestones, Sakura, and Garden

Curriculum completion remains the meaningful milestone boundary. Existing Garden progression continues to derive from actual learning state; moving on the map never awards Garden growth. If Journey learning creates a new mastery, kana, grammar, conversation, or curriculum state, the existing Garden synchronizer can surface its normal growth/unlock event. Sakura receives chapter-start, completion, return, prerequisite, and milestone context through the existing event boundary, with no Journey-specific answer handling.

Focus Quest remains a first-class escape hatch from Home and the Journey map. Its answers contribute to mastery and therefore can naturally make Journey prerequisites or Garden elements available, but selecting or completing a Focus duration grants no artificial Journey progress.

## Daily and weekly prompts

The existing daily quests and weekly study-day marker remain optional secondary prompts. They do not gate curriculum nodes or recommendations. They stay visible as small encouragements while the Journey answers the higher-priority question of what to do next; no energy, tickets, currencies, or punishment mechanics were introduced.

## Persistence and resume integrity

Journey progression is derived from `curriculum`, reviews, kana, grammar, conversations, and the existing Garden state. No duplicate Journey progress counter is persisted. The active-session checkpoint now preserves standard Journey exits as well as Focus exits, including node ID, position, score, answered state, and conversation scenario identity. Home offers Continue, and resuming advances past a completed final question instead of replaying it. Existing attempt IDs and idempotent completion guards prevent duplicate XP, mastery, curriculum completion, Garden growth, or Sakura events.

v0.5 saves merge safely with the new schema because Journey adds no required save fields. Legacy/imported saves derive their current map and recommendation from their learning state. Optional UI selection is transient and is not treated as progress.

## Accessibility, mobile, and motion

The map uses semantic buttons and text for every node, status, objective, progress value, and prerequisite. The visual rail is supplementary. Existing focus states, contrast, font scaling, mobile navigation, and reduced-motion setting support remain active. On small screens, the map becomes a readable vertical path and recommendation/detail cards stack instead of compressing into a desktop grid.

## Verification

The regression suite retains all v0.3/v0.4/v0.5 tests and adds deterministic recommendation, active-session direction, map status, prerequisite, and progress coverage. Manual QA checks a new save, Home recommendation, Journey map/detail, launch through the canonical engine, interruption and resume, locked prerequisites, Focus fallback, Garden navigation, reload/import compatibility, mobile stacking, keyboard controls, reduced motion, and existing Sakura/Garden behavior. Production build, syntax checks, and whitespace validation are run before release.

## Known limitations and v0.7 extension points

The map uses the current 12 curriculum nodes and simple chapter groupings; it does not yet support branching paths or a separate milestone timeline. Conversation checkpoints can resume known scenario IDs, while future activity types may need richer serialized payloads. v0.7 can add explicit milestone nodes, richer return recommendations, audio-ready activities, cultural discovery cards, and bespoke chapter art without changing canonical learning or Garden truth.
