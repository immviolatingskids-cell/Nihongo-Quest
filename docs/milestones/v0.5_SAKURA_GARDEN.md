# Nihongo Quest v0.5 — Sakura Garden

## Progress model

The Garden is derived from the existing learning state. It does not award growth for opening a screen, selecting a Focus duration, or repeating low-value actions. The engine calculates five meaningful counts:

- 🌸 Blossoms: vocabulary records at mastery 4 or higher.
- 🪨 Stones: kana with at least three correct answers.
- 🏮 Lanterns: learned grammar structures from the curriculum.
- 🐦 Songbirds: completed conversations.
- 🌿 Branches: completed curriculum chapters.

The transparent growth score is `blossoms × 4 + kana + grammar × 3 + conversations × 4 + branches × 5`. Garden levels use bounded thresholds: Seed (0), Sprout (8), Young Tree (22), First Bloom (42), Flourishing (70), Moonlit Garden (105), and Full Bloom (150).

## Learning-to-Garden mapping

The existing Garden illustration remains the baseline. Deterministic CSS layers reveal a first blossom, kana path stone, branch, grammar lantern, songbird, moonlit accents, and pond details as their requirements are met. Each element has a text label and the scene has an accessible summary, so artwork is not the only progress signal.

The Garden screen now shows level, score, progress to the next level, the next meaningful unlock, recent growth, and a compact contribution ledger. The Garden is available through the main navigation and stacks its summary and ledger for smaller screens.

## Unlocks and events

Unlock IDs are deterministic and stored only as a bounded milestone ledger. Derived counts remain the source of truth. `syncGardenProgress()` compares the current derived counts with the last observed counts and emits `GARDEN_GROWTH`, `GARDEN_LEVEL_UP`, or `GARDEN_UNLOCK` through the existing companion boundary. Repeated syncs and duplicate curriculum completion do not re-award or re-notify unlocks.

Sakura receives short Garden-aware dialogue through the existing priority and throttle system. Lesson/session completion remains able to win over lower-priority reactions. Recent growth is shown only when a meaningful category changes. Focus Quest completion can mention Garden growth when the session genuinely changed the derived score; choosing a duration alone has no effect.

## Persistence and compatibility

Existing saves remain compatible. The small `garden` save section stores only event-edge metadata: initialization state, last observed counts, recent messages, and milestone IDs/dates. Garden level and score are always recalculated from reviews, kana, grammar, conversations, and curriculum. Legacy/imported saves are baselined without inventing historical growth notifications. Garden state survives reload, browser restart, Focus interruption, export, and import.

There is no decay: absence never removes levels, unlocks, blossoms, or other traces of learning.

## Accessibility and motion

Garden progression is available as text, labels, counters, and progress descriptions. Existing keyboard controls, contrast, font scaling, mobile breakpoints, and `prefers-reduced-motion`/reduced-motion setting support remain in force. Growth layers use a short calm reveal transition, disabled automatically by the shared reduced-motion class.

## Verification

The regression suite includes the v0.3/v0.4 contracts plus Garden contribution calculations, level boundaries, legacy compatibility, unlock persistence, duplicate-event protection, and score derivation. Manual QA checks the Garden nav and empty state, learned traces, Sakura event behavior, Focus integration, reload/import compatibility, mobile stacking, and reduced motion. Production build and syntax checks are run before release.

## Known limitations and v0.6 extension points

The current scene uses a bounded set of emoji/CSS overlays rather than bespoke artwork for every unlock. Conversation progress is counted per completed scenario ID, while repeated practice of an already completed conversation does not create additional Garden growth. v0.6 could add richer milestone detail, seasonal presentation that never removes earned progress, or a more granular listening contribution without changing the derived model or canonical learning recorder.
