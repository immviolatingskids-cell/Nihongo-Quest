# Nihongo Quest v0.4 — Focus Quest

## Architecture

Focus Quest is an adapter over the v0.3 learning engine. `buildFocusSession(duration)` selects from existing due reviews, recent mistakes, focused kana reinforcement, and new material, then creates the same canonical questions used by other sessions. It does not introduce a second progress or answer system.

## Duration and composition

The available commitments are 2, 5, and 10 minutes. They map to predictable approximate budgets of 3, 6, and 10 questions rather than a hard countdown. The composer prioritises due material, then mistakes, then reinforcement, and finally new material. Each item retains its existing source reason.

## Focus UI

Home presents a prominent low-friction Focus Quest card with three choices and short, non-technical descriptions. Focus sessions use a calm single-column shell, current-question-first layout, lightweight progress, a saved-progress note, and a safe “Stop whenever you want” action. The normal dashboard navigation is removed from the active Focus shell without changing the rest of the product.

## Resume and interruption safety

The existing `activeSession` checkpoint now records focus mode, duration, index, score, and session identity. Returning to Home exposes Continue Focus Quest and Start fresh. Continuing rebuilds the same duration budget and restores the approximate question position; starting fresh clears only the checkpoint and never reverses recorded answers. Every completed answer remains protected by the v0.3 attempt ID guard.

## Completion and momentum

Focus completion is compact: questions completed, strengthened answers, tricky answers, a calm Sakura message, Finish, and an optional +2 minute Keep going action. The extension appends another engine-composed short batch rather than restarting the session. Early exit records local metadata and carries no penalty.

## Sakura behavior

Focus answer events use the existing event boundary and a longer cooldown, reducing chatter during short sessions. Meaningful streak and completion events remain eligible, and the existing non-blocking/reduced-motion behavior is preserved.

## Persistence and instrumentation

`focus.lastDuration` remembers the most recent choice. A bounded local `focus.sessions` history records duration, attempted/completed counts, completion versus voluntary exit, and extension count. No analytics service or remote tracking is introduced.

## Verification

The regression suite covers all three duration profiles, bounded composition, source metadata, preference memory, resume-position calculation, canonical evaluation, idempotent recording, legacy saves, and the existing v0.3 lifecycle. The production build and JavaScript syntax checks pass. Manual browser QA covered correct → incorrect → streak recovery → completion → return, early exit before and after an answer, resume, Start fresh, the +2 minute extension, calm Focus feedback, keyboard-accessible buttons, and the Focus-specific shell. Reduced-motion and mobile rules remain shared with v0.3.

## Known limitations and future hooks

The checkpoint stores a compact position rather than serializing every generated question, so resume rebuilds a fresh composition and restores an approximate position. Elapsed time is not shown as a countdown. Future work can add a richer local resume record or adaptive time estimation without changing progress recording or Sakura events.
