# Nihongo Quest v0.7 — Voices of Japan

v0.7 adds an audio layer without creating a second learning model.

## Progression and audio boundary

`src/audio.js` is the only runtime audio boundary. Requests carry a stable content ID, category and Japanese text. The provider order is local asset (when a manifest-backed asset exists), browser Japanese TTS, then a graceful unavailable result. Sakura lines use the same boundary with low priority so they never interrupt a learning prompt.

The current release intentionally ships no external or paid runtime dependency. Browser `speechSynthesis` is the fallback; audio remains optional and the UI explains when it is unavailable.

## Preferences and persistence

Voice, speed (`slow`, `normal`, `fast`) and autoplay preferences live in the versioned save under `audio`. Legacy saves merge safely with defaults. Sound can still be disabled globally. Playback is replace-on-new-request, deduplicated for rapid repeated taps, and tolerant of missing voices.

## Learning integration

Vocabulary, examples, kana, conversation prompts and listening questions use semantic audio requests. Listening is a canonical word question stage, so answers update the existing review skill, XP, streaks, Sakura events and Garden exactly like other answers. The transcript is revealed only after answering. Focus sessions may include listening when Japanese audio is available; selecting or completing Focus itself never grants audio-only progress.

## Coverage and diagnostics

Run `npm run audio:report` to enumerate kana, vocabulary, example, grammar and conversation coverage. The report separates content coverage from local assets and documents the TTS fallback. `audioDiagnostics()` exposes capability, Japanese voices and preferences for the settings/developer surface.

## Accessibility and failure behavior

Playback controls are keyboard buttons with labels. Audio is never the sole source of answer feedback: listening questions provide a post-answer transcript. Reduced-motion behavior continues to be controlled by the existing setting and `prefers-reduced-motion` CSS. Offline use works for all non-audio learning; unavailable audio produces a concise notice rather than a broken lesson.

## Tests and limitations

The audio service is Node-safe and tested for provider resolution, unavailable environments, speed/voice metadata and save compatibility. Existing v0.3–v0.6 engine tests remain the regression suite. No full Sakura voice pack, generated audio catalogue, waveform editor, pronunciation scoring or remote asset hosting is included yet.

## v0.6 extension points

Stable IDs and the coverage script leave room for checked-in audio assets, a manifest validator, downloadable voice packs, richer Sakura reactions and listening-specific analytics without coupling those features to the UI or progress engine.
